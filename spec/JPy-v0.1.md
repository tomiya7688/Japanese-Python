# JPy 言語仕様 v0.1.0（ドラフト）

- **仮称:** JPy（Japanese Python）
- **拡張子:** `.jpy`
- **仕様の状態:** v0.1 ドラフト（本書が規範。ツール・README・テストよりも本書を優先する）
- **基準言語:** Python 3.12 の構文・実行意味論
- **変換先:** UTF-8 の `.py`（`compile` モード）、または実行前にメモリ内で作る Python コードオブジェクト（`run` モード）

## 1. 目的と非目的

JPy は、**Python の文（statement）の主要な構文を日本語で書けるようにする、Python 向けのトランスパイル言語**である。Python の式、インデント、標準ライブラリ、外部ライブラリ、型注釈、オブジェクトモデル、実行意味論は原則変更しない。

TypeScript と JavaScript の関係に似せるのは、**上位ソースを既存言語へ変換する開発モデル**である。v0.1 では TypeScript のような独自の静的型検査・型付け拡張は提供しない。

### 設計原則

1. **Python 優先:** 変数代入、関数呼び出し、属性アクセス、スライス、演算子、内包表記などの式は Python のまま書く。
2. **文の日本語化:** `def`、`if`、`for`、`return` などに日本語の表記を追加する。**Python の `if` や `for` は引き続きそのまま書ける。**
3. **限定的な日本語語順:** 後置の `条件 なら:` と `式 を戻す` を認める。それ以外の語順変更は原則行わない。
4. **意味の保存:** 日本語構文と対応する Python 構文は同じ動作をする。新しい実行時機能は追加しない。
5. **混在可能:** ひとつの `.jpy` ファイル内で Python の元の構文と JPy の構文を混在できる。ただし「8. 識別子との衝突」に記載する例外がある。

## 2. 字句・ソース規則

- ソースは UTF-8。改行、コメント `# ...`、文字列、f-string、括弧、コロン、カンマ、インデントは Python 3.12 と同じ。
- ブロックは Python と同様にインデントで表す。推奨はスペース 4 個。`{}` をブロック区切りには使用しない。
- 日本語・英語の変数名、関数名、クラス名を認める。ただし Python の識別子規則に従う。
- `True` / `False` / `None`、`and` / `or` / `not` / `in` / `is`、算術・比較演算子は v0.1 では **Python の表記をそのまま使用**する。
- 日本語構文の特殊語は、**文頭**または**最上位の文末**という構文位置で認識する。文字列、コメント、括弧内部に現れても変換しない。
- 「最上位」は丸括弧・角括弧・波括弧の内側ではない位置をいう。変換は Python のトークン列を解析して行い、生の文字列置換をしてはならない。
- JPy の新規構文は原則「1 論理行に 1 文」。日本語のヘッダは `:` の後で改行・インデントされたスイートを持つ。Python の元の構文については Python 仕様どおり。

## 3. 日本語構文一覧（規範）

表の `式`、`対象`、`引数` はそれぞれ Python の expression、for-loop target、parameter list に従う。

| JPy | 変換先 Python | 備考 |
|---|---|---|
| `関数 名前(引数):` | `def 名前(引数):` | 引数の初期値・型注釈・`-> 型` はそのまま |
| `クラス 名前:` | `class 名前:` | `クラス 名前(基底):` も許可 |
| `もし 式 ならば:` | `if 式:` | **正式な日本語 if 構文**。`ならば` と `:` は必須 |
| `式 なら:` | `if 式:` | **日本語語順 1**。行末の `なら` のみ認識 |
| `それ以外でもし 式 ならば:` | `elif 式:` | **正式な日本語 elif 構文**。`ならば` と `:` は必須 |
| `それ以外:` | `else:` | Python と同様、`if` / `for` / `while` / `try` 等に従属 |
| `各 対象 を 式 から:` | `for 対象 in 式:` | `を` と末尾の `から` が区切り |
| `繰り返し 式:` | `while 式:` | Python の `while` と同じ |
| `戻す 式` | `return 式` | 関数内で使用 |
| `戻す` | `return` | 戻り値なし |
| `式 を戻す` | `return 式` | **日本語語順 2**。`を戻す` はひとつの語 |
| `抜ける` | `break` | ループ内部 |
| `続ける` | `continue` | ループ内部 |
| `何もしない` | `pass` | 空のブロック等で使用 |
| `読み込む モジュール` | `import モジュール` | v0.1 は 1 モジュールずつ |
| `読み込む モジュール として 別名` | `import モジュール as 別名` | `として` はこの位置のみ |
| `試す:` | `try:` | 例外処理 |
| `捕まえる 例外:` | `except 例外:` | 例外式は Python の式 |
| `捕まえる 例外 として 名前:` | `except 例外 as 名前:` | `として` はこの位置のみ |
| `捕まえる:` | `except:` | 裸の except（Python と同じ制限） |
| `最後に:` | `finally:` | 例外処理 |

これらに記載がない `with`、`async`、`await`、`yield`、`raise`、`assert`、`lambda`、`match` / `case`、`from ... import ...`、デコレータ、内包表記などは **標準 Python の構文のまま使用できる**。v0.1 での日本語表記は定義しない。

## 4. 語順変更の厳密な範囲

### 4.0 正式な if 構文: `もし 式 ならば:`

```jpy
もし 点数 >= 60 ならば:
    print("合格")
```

これは Python の `if 点数 >= 60:` と等価である。`もし` に続く条件は Python の式であり、`ならば` は最上位のヘッダ末尾、`:` はブロック導入のために必須である。省略形 `もし 式:` は **JPy v0.1 では認めない**。`もし 式 なら:` も認めない。

**日本語の elif も `それ以外でもし 式 ならば:` が正式形。** `それ以外でもし 式:` や `それ以外でもし 式 なら:` は認めない。元の `if` / `elif` と同様に、対応する if/elif 節の後に続ける。

**Python の構文は常に利用できる。** `if 式:`、`elif 式:`、`else:`、`for 対象 in 式:` をそのまま記述してよく、JPy の `もし`、`それ以外でもし`、`各` と同じ `.jpy` ファイル内・同じ条件分岐で混在できる。元の Python 構文は変換しない。

### 4.1 `式 なら:`

```jpy
点数 >= 60 なら:
    print("合格")
```

以下と等価である。

```python
if 点数 >= 60:
    print("合格")
```

- `なら` はブロックを導入するヘッダの**末尾（最上位）**にある場合だけ特別扱いする。
- `もし 式 なら:` という混合ヘッダは認めない。`もし 式 ならば:` または `式 なら:` を使う。
- `elif` の後置版は v0.1 では認めず、`それ以外でもし 式 ならば:` を使う。

### 4.2 `式 を戻す`

```jpy
関数 足す(a, b):
    a + b を戻す
```

以下と等価である。

```python
def 足す(a, b):
    return a + b
```

- `を戻す` は**ひとつの語**として、単純文の末尾（コメントを除く）に置く。`を 戻す` は認めない。
- 手前の `式` は、Python の式として有効でなければならない。`x = 1 を戻す` のような代入文は認めない。
- `を戻す` のない `戻す 式` も同じ意味で使用できる。
- `戻す`、`式 を戻す` は Python の `return` と同じく関数の外では使えない。

### 4.3 `各 対象 を 式 から:`

```jpy
各 名前 を ["葵", "蓮"] から:
    print(名前)
```

```python
for 名前 in ["葵", "蓮"]:
    print(名前)
```

`対象` には Python の `for` の代入先として有効な変数名、タプル分解などを記述できる。`を` は対象と式の間にある最上位の区切り、`から` は末尾の最上位の区切りとして扱う。曖昧な区切りは構文エラーとする。

## 5. 文法の概略（EBNF 風）

以下は**追加される構文の概略**であり、Python 3.12 の文法全体を置換する完全な EBNF ではない。

```text
jpy_statement := python_statement
               | function_def | class_def | if_header | elif_header | else_header
               | for_header | while_header | return_statement
               | break_statement | continue_statement | pass_statement
               | import_statement | try_header | except_header | finally_header

function_def   := "関数" PY_NAME "(" PY_PARAMETERS ")" ["->" PY_EXPR] ":"
class_def      := "クラス" PY_NAME ["(" PY_CLASS_ARGS ")"] ":"
if_header      := "もし" PY_EXPR "ならば" ":" | PY_EXPR "なら" ":"
elif_header    := "それ以外でもし" PY_EXPR "ならば" ":"
else_header    := "それ以外" ":"
for_header     := "各" PY_FOR_TARGET "を" PY_EXPR "から" ":"
while_header   := "繰り返し" PY_EXPR ":"
return_statement := "戻す" [PY_EXPR] | PY_EXPR "を戻す"
break_statement  := "抜ける"
continue_statement := "続ける"
pass_statement   := "何もしない"
import_statement := "読み込む" PY_MODULE ["として" PY_NAME]
try_header      := "試す" ":"
except_header   := "捕まえる" [PY_EXPR ["として" PY_NAME]] ":"
finally_header  := "最後に" ":"
```

`PY_EXPR` / `PY_PARAMETERS` / `PY_FOR_TARGET` / `PY_MODULE` / `PY_CLASS_ARGS` は Python 3.12 の該当規則に委譲する。`PY_EXPR` を文字列検索で分割してはならず、トークン・括弧深さに基づいて文末の構文語を切り出す。

## 6. 代表例と期待される動作

### JPy 入力: `main.jpy`

```jpy
関数 判定(点数: int) -> str:
    もし 点数 >= 80 ならば:
        戻す "優"
    それ以外でもし 点数 >= 60 ならば:
        "合格" を戻す
    それ以外:
        戻す "不合格"

各 点数 を [55, 65, 82] から:
    print(判定(点数))
```

### 変換先: `main.py`

```python
def 判定(点数: int) -> str:
    if 点数 >= 80:
        return "優"
    elif 点数 >= 60:
        return "合格"
    else:
        return "不合格"

for 点数 in [55, 65, 82]:
    print(判定(点数))
```

### 標準出力

```text
不合格
合格
優
```

### 日本語語順の条件と Python の構文の混在

```jpy
import math

関数 円の面積(半径: float) -> float:
    半径 >= 0 なら:
        math.pi * 半径 ** 2 を戻す
    それ以外:
        raise ValueError("半径は負にできません")
```

この例は `import` と `raise` が標準 Python のまま混在できることも示している。

## 7. Python 互換性・実行意味論

- 日本語構文は表に記載した Python 構文へ変換し、**変換後の Python と同じ意味**で実行する。
- Python の標準・サードパーティーライブラリは通常の `import` で利用できる。`読み込む math` のような書き方は通常の `import math` に変換するだけである。
- 代入 `x = 1`、型注釈 `x: int = 1`、関数引数の型注釈、戻り値の型注釈は Python そのまま。独自の型推論・型エラー診断は導入しない。型検査ツールを使う場合は変換後の `.py` を対象とする。
- `.jpy` から別の `.jpy` を Python の通常の import 機構で**直接**読み込む機能は v0.1 では定義しない。依存先の `.jpy` を `.py` に事前変換する運用とし、自動変換 import hook は将来の検討対象とする。
- JPy 独自の標準ライブラリ、組み込み関数、専用 VM、独自バイトコードは存在しない。

## 8. 識別子との衝突と優先順位

Python では日本語も識別子になり得るため、**JPy は厳密な意味で「すべての合法 Python ソースの上位集合」とはしない**。たとえば `戻す` だけの行は Python では名前参照になり得るが、JPy では `return` 文と解釈する。

衝突規則を次のように定める。

1. JPy の構文に一致する文は、対応する日本語構文として解釈する。
2. 一致しない文は、Python の標準構文として解釈する。
3. 字句的に現れただけの文字列やコメントは JPy 構文とはみなさない。
4. 文中に登場する Python 識別子としての `戻す` などは原則利用可能。例: `戻す = 10` や `print(戻す)` は Python と同じ。ただし `戻す` 単独行は JPy の `return` と解釈する。
5. `それ以外でもし` は `それ以外` より優先してひとつの構文語として認識する。`ならば` は構文上の文末マーカーであり、文字列・コメント内では解釈しない。

この例外を明示したうえで、通常の Python コードとの**実用上の混在互換性**を目標とする。

## 9. エラー・変換・行番号

- トークン化し、JPy の文を認識し、対応する Python の文へ変換し、Python の構文解析器で検証する。
- 日本語の構文語は**文字列置換しない**。`print("もし x なら:")` や `# 戻す` の文字列・コメント内容はそのままとする。
- 行・列の診断は元の `.jpy` の位置を指す。少なくとも**行番号は元ソースと一致**させる。JPy v0.1 の変換では不要な行を挿入・削除しない。
- Python の意味的制約（関数外の `return`、ループ外の `break`、`except` の組み合わせなど）は変換後に Python の検証で判定する。
- 未定義の日本語構文は勝手に解釈せず、Python で有効でなければ構文エラーを出す。
- 日本語構文のブロックヘッダに続くインラインスイート（例: `もし x ならば: print(x)`）は v0.1 では非対応。改行してインデントする。標準 Python のインラインスイートはそのまま使える。

## 10. 参考ツールの意味と互換性契約（規範）

**JPy の主成果物は言語変換仕様であり、CLI は参考実装にすぎない。** ただし、以下のモードの意味は v0.1 の公開後に入れ替えてはならない。

### 10.1 `compile`: Python ファイルへの純粋変換

```sh
jpy compile main.jpy                # デフォルトで build/main.py を出力
jpy compile main.jpy -o main.py     # 出力先を明示
jpy compile main.jpy -o main.py --force  # 既存ファイルを明示的に上書き
```

このモードの契約:

1. `.jpy` の言語構文を対応する Python 構文に変換し、UTF-8 の **`.py` ファイルを書き出す**。
2. **アプリケーションコードを実行しない**。CPython による構文・意味的制約の静的検証は許可される。
3. 生成 `.py` は JPy ランタイムに依存せず、**独立に CPython で読み込み・実行できる**。
4. 入力の `.jpy` に変更を加えず、既存の出力 `.py` を暗黙に上書きしない。
5. Python 生成物の物理行番号は元の `.jpy` と一致する。

### 10.2 `run`: 元の `.jpy` を直接 CPython で実行

```sh
jpy run main.jpy
jpy run main.jpy -- arg1 arg2
```

このモードの契約:

1. **元の `.jpy` を実行対象とする**。ユーザーは `.py` への明示的変換を必要としない。
2. JPy 構文を **メモリ内でだけ** Python 構文に変換し、同じ CPython プロセスでコードオブジェクト化して実行する。**変換済み `.py` を一時ファイルとしても書き出さない**。
3. 独自 JPy VM や独自 Python 実装は利用しない。未変換の日本語文法そのものを CPython に直接解釈させる方式でもない。
4. `__name__ == "__main__"`、`__file__`、`sys.argv`、スクリプト所在ディレクトリからの Python import を通常の CPython スクリプト実行に近づける。`__file__` とトレースバックの対象パスは `.jpy` である。
5. `run` は**ファイル変換・ビルド成果物生成の手段ではない**。アプリケーション自身が行うファイル出力や Python 標準の import キャッシュはこの禁止範囲に含めない。

### 10.3 共通内部実装と、混同してはならない意味

構文変換器自体は両モードで **同じ変換規則**を使う。一方、**出力と副作用の契約は別**である。`compile` が実行を始めたり、`run` が実行のための `.py` を残したりする変更は互換性を破壊する。

特定の CLI 名・ライブラリ名は仮称であり、公開前に他プロジェクトとの衝突を確認すること。

### 10.4 PyInstaller / Nuitka との連携（規範）

**PyInstaller と Nuitka には `compile` モードで生成された通常の `.py` を入力する。** 両ツールへ `.jpy` を直接渡すこと、あるいは `run` モードをバンドルの入口にすることを v0.1 の互換性要件にしてはならない。

```sh
jpy compile main.jpy -o build/main.py
python -m PyInstaller --onefile build/main.py
python -m nuitka --mode=standalone build/main.py
# standalone で動作確認してから
python -m nuitka --mode=onefile build/main.py
```

- この方法では配布された Python アプリケーションへ JPy 実行ランタイムを追加する必要はない。
- `.jpy` 依存モジュールは v0.1 ではすべて事前に `.py` に変換して、通常の Python モジュール配置を保つ。`.jpy` の直接 import は非対応。
- PyInstaller / Nuitka 固有の追加依存、動的 import、データ同梱、相対ファイルパス、ネイティブコンパイラの制約は各ツールに従う。任意の環境でのパッケージング成功までは JPy 仕様が保証しない。
- 将来、便利コマンドを追加する場合も **内部で `compile` 由来の通常の `.py` を渡すだけ**とし、`compile` / `run` の意味を変更してはならない。

## 11. v0.1 の非対応範囲

以下は JPy 構文として**まだ追加しない**。標準 Python の構文は引き続き使用可能。

- `真`、`偽`、`無`、`かつ`、`または` など、値・論理演算子の日本語化
- 日本語語順の任意の自然言語解釈、`a を b に加える` のような自然文演算
- `非同期 関数`、`... の中で`（with）、`... から ... を読み込む` などの追加日本語文法
- `.jpy` モジュールの自動 import、プロジェクト全体の依存関係解決
- 独自型システム、型検査器、JPy 専用の組み込み関数
- JPy 文のセミコロン連結、JPy ブロックの 1 行スイート
- Python 3.12 より新しい専用構文の動作保証（対象バージョンの拡張として別途対応）

## 12. 最低限の受け入れ基準

v0.1 の実装は最低限、以下を満たすこと。

1. 「6. 代表例」が記載どおりの Python に変換され、期待する 3 行を出力する。
2. `もし 式 ならば:` と `式 なら:`、および Python の `if 式:` が同じ条件分岐の意味を持つ。
3. `戻す 式` と `式 を戻す` が同じ戻り値の意味を持つ。
4. Python の `if`・`elif`・`for` を含む標準構文、式・代入・呼び出し・型注釈・ライブラリ import がそのまま使え、日本語構文と混在できる。
5. 文字列・コメント中の日本語構文語は変化しない。
6. 日本語構文と英語の標準 Python 構文が同じファイル内で動作する。
7. 構文エラーの行番号は元の `.jpy` の行番号と一致する。
8. `jpy compile` で出力した `.py` は、JPy 実行環境なしで CPython が実行できる。
9. `compile` はユーザーのアプリケーションを実行せず、既存のファイルを上書きしない（明示オプションは除く）。
10. `run` は生成 `.py` を一切書き出さず、元の `.jpy` のファイル名と引数を維持して CPython で実行する。
11. PyInstaller / Nuitka への入力は、`compile` で生成した通常の `.py` であり、`run` でない。
12. `それ以外でもし 式 ならば:` は `elif 式:` に等価であり、末尾の `ならば` を欠く日本語 elif を受け入れない。Python の `elif` は変換せずに使用できる。

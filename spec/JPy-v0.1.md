# JPy 言語仕様 v0.1.0 — 文法決定版

- **名称:** JPy（Japanese Python、仮称）
- **状態:** v0.1 文法決定版・リリース前ドラフト。本書が規範であり、参考実装・README・テストより優先する。
- **基準:** Python 3.12 の構文。実行意味論は変換先を実行する CPython に従う。
- **ソース:** UTF-8 の `.jpy`。生成物は通常の `.py`。
- **互換性:** Python 3.12 / 3.13 を参考実装の検証対象とする。新しい Python の構文・意味論を無条件に保証しない。

## 1. 目的と原則

JPy は **Python の基本的な文に日本語表記を追加する言語変換仕様**である。言語仕様が主成果物であり、変換・実行ツールは仕様の実装と検証を補助する。

Python の式、型注釈、ライブラリ、オブジェクトモデル、評価順、例外、スコープを変更しない。独自 VM、独自型システム、専用の組み込み関数は導入しない。TypeScript に似せるのは「既存言語に変換する開発モデル」であり、型システムではない。

Python 本来の `if`、`elif`、`for`、`while`、`def` などを引き続き使用できる。同じファイル・ブロック・条件分岐で日本語表記と英語表記を混在できる。ただし日本語の構文語と識別子が衝突する位置については §8 に従う。**合法な Python ソースすべての厳密な上位集合を主張しない。**

## 2. 字句と書式

UTF-8（先頭 BOM は許可）を使う。改行は LF / CRLF / CR を受け入れ、出力では LF に正規化できる。BOM は出力から除去できる。UTF-8 以外のエンコーディング宣言は認めない。

ブロックは半角 `:` と改行・インデントで表す。推奨は半角スペース4個。全角空白や全角記号を構文記号として自動補正しない。Python のインデント規則に従う。

日本語の構文語と引数・式は **半角スペースまたはタブで区切る**。`ならば`、`の間`、`を戻す` はそれぞれ一つの語である。`の 間`、`を 戻す` は同じ構文ではない。`:` の直前の空白は任意。

括弧内の式・引数・文字列が複数行にまたがる記述は許可する。ただし、削除・移動する構文区切りそのものは同じ物理行に置く。例として `) から (` や `) ならば:` の区切りを改行しない。JPy の構文は1論理行に1文とし、インラインスイートとセミコロン連結は認めない。英語の Python 文だけで書くインラインスイートは使える。

`#` コメント、通常文字列、raw文字列、bytes文字列、f-string はPythonのままである。f-string の埋め込み式もPythonの式のままとし、その内部にJPy文法を追加しない。構文語はトークンと文の位置に基づいて認識し、生の文字列置換を行わない。正規化を除いて文字列・コメントの内容を改変しない。

## 3. 日本語表記と変換規則（規範）

表中の `式`、`対象`、`名前`、`引数` は対応するPythonの文法要素に従う。`[...]` は省略可能な構文要素を示すメタ表記であり、入力する角括弧ではない。

| JPy | Python | 規則 |
|---|---|---|
| `もし 条件 ならば:` | `if 条件:` | `ならば` は必須 |
| `それ以外でもし 条件 ならば:` | `elif 条件:` | `ならば` は必須 |
| `それ以外:` | `else:` | if / for / while / try に従属 |
| `条件 なら:` | `if 条件:` | 既存の後置形として維持 |
| `繰り返し 対象 を 式 から:` | `for 対象 in 式:` | **汎用反復の正式形** |
| `各 対象 を 式 から:` | `for 対象 in 式:` | 既存ソース用の互換表記 |
| `繰り返し 名前 が 開始 から 終了 まで:` | `for 名前 in range(開始, 終了):` | 終了値は含まない |
| `繰り返し 名前 が 開始 から 終了 まで 増分 ずつ:` | `for 名前 in range(開始, 終了, 増分):` | 負の増分も使える |
| `条件 の間:` | `while 条件:` | 条件が真である間 |
| `抜ける` | `break` | 最も内側のループを終了 |
| `続ける` | `continue` | 最も内側のループの次の反復へ |
| `何もしない` | `pass` | 空文 |
| `関数 名前(引数):` | `def 名前(引数):` | 型注釈・戻り値注釈等はPythonのまま |
| `クラス 名前[(基底等)]:` | `class 名前[(基底等)]:` | 継承・メタクラス等はPythonのまま |
| `戻す [値]` | `return [値]` | 値なしも許可 |
| `値 を戻す` | `return 値` | 既存の後置形として維持 |
| `読み込む モジュール [として 別名]` | `import モジュール [as 別名]` | 日本語形は1文1モジュール |
| `試す:` | `try:` | 例外処理 |
| `捕まえる [例外 [として 名前]]:` | `except [例外 [as 名前]]:` | 裸のexceptも許可 |
| `最後に:` | `finally:` | 後処理 |
| `投げる [例外 [from 原因]]` | `raise [例外 [from 原因]]` | 値なしは再送出。`from` は英語 |
| `使う 式 [として 対象]:` | `with 式 [as 対象]:` | 日本語形は1コンテキストマネージャー |
| `確認する 条件[, メッセージ]` | `assert 条件[, メッセージ]` | 最適化時の省略もPythonと同じ |

日本語形の別名指定では `として` の代わりに英語の `as` も許可する。新しい日本語の同義語はこの表以外に追加しない。

## 4. 各構文の意味と境界条件

### 4.1 条件分岐

```jpy
もし 点数 >= 80 ならば:
    print("優秀")
それ以外でもし 点数 >= 60 ならば:
    print("合格")
それ以外:
    print("不合格")
```

`もし 条件:`、`もし 条件 なら:`、`それ以外でもし 条件:` は認めない。前置形に `ならば` が必要であり、後置形 `条件 なら:` とは別の構文である。後置のelifは追加しない。条件の真偽判定はPythonの規則に従う。英語の `elif` / `else` を途中に混ぜてもよい。

### 4.2 リスト・辞書・イテレーターを使う汎用反復

```jpy
繰り返し 果物 を ["りんご", "みかん"] から:
    print(果物)

繰り返し (番号, 果物) を enumerate(果物一覧) から:
    print(番号, 果物)

繰り返し (名前, 点数) を 成績.items() から:
    print(名前, 点数)
```

`繰り返し 対象 を 式 から:` を正式形とする。`各` は互換表記として残すが、新しい例は `繰り返し` を使う。`対象` はPythonのforの代入先で、分解代入も可能。`式` は一度評価され、その反復可能オブジェクトを順に処理する。単に回数だけ繰り返す場合は `繰り返し _ を range(5) から:` と書ける。別の「5回」構文は追加しない。

### 4.3 数値範囲と増分

```jpy
繰り返し i が 0 から 5 まで:
    print(i)  # 0, 1, 2, 3, 4

繰り返し i が 0 から 10 まで 2 ずつ:
    print(i)  # 0, 2, 4, 6, 8

繰り返し i が 5 から 0 まで -1 ずつ:
    print(i)  # 5, 4, 3, 2, 1
```

**`まで` は終了値を含まない。** 通常の日本語の解釈ではなく、Pythonの `range` への対応を優先する。開始値の省略は認めず、増分省略時は2引数の `range` を生成する。増分の暗黙値は1で、開始値が終了値より大きくても自動で降順にしない。

開始・終了・増分はそれぞれPythonの式。Pythonの引数評価順で一度ずつ評価する。タプル式は1引数のまま渡し、カンマで `range` の引数を意図せず増やさない。JPy構文の引数位置に `*args`、`stop=...` などのPython呼び出し用構文は追加しない。

生成する `range` は普通のPythonの名前である。スコープ内で `range` が上書きされていれば、その名前解決も同じように適用される。組み込み `range` を使う通常の場合、増分0は `ValueError`、整数として扱えない値は `TypeError`、条件に合う要素がなければ0回の反復となる。JPyは独自のチェックや隠れた組み込み関数参照を追加しない。

範囲構文の反復変数は単独のPython識別子。区切り語 `が`、`から`、`まで`、`ずつ` と曖昧になる式は括弧で囲む。たとえば変数 `から` を開始値に使うなら `(から)` と書く。

### 4.4 while・ループのelse・ループ制御

```jpy
i = 0
i < 5 の間:
    i += 1
```

`条件 の間:` は `while 条件:` であり、条件は反復のたびに評価する。以前のドラフトにあった `繰り返し 条件:` をwhileとしては扱わない。無限ループは `True の間:` と書ける。

for / while に続く `それ以外:` はPythonのループelseである。反復可能オブジェクトを使い切る、またはwhile条件が偽になることで終了した場合に実行する。0回の反復でも対象となる。`抜ける` / `break` で終了した場合は実行しない。`return` や例外による脱出もPythonの規則に従う。

`続ける` は残りの本体を飛ばして次へ進む。`抜ける` と `続ける` の適用先は最も内側のループ。`何もしない` は反復制御ではなく空文である。

### 4.5 関数・クラス・戻り値

`関数` と `クラス` の後の宣言部分はPythonの対応する宣言を使う。位置専用引数 `/`、キーワード専用引数 `*`、`*args`、`**kwargs`、デフォルト値、型注釈、型パラメーター、戻り値注釈、継承、メタクラスの規則を変更しない。`self`、`cls`、`__init__` 等を日本語に改名しない。デコレーターは `@...` のまま使う。

`戻す` は値なしのreturn、`戻す 値` と `値 を戻す` は同じ値を返す。`戻す a, b` と `a, b を戻す` はタプルを返す。代入文 `a = 1 を戻す` は認めない。関数外のreturn等の文脈制約はPythonの検証に委譲する。

### 4.6 import

```jpy
読み込む math として 数学
from pathlib import Path
from .helpers import calculate as 計算
```

日本語形は1モジュールずつ読み込む。複数モジュール、選択的import、相対import、ワイルドカードimportには通常の `import` / `from ... import ...` を使う。**v0.1では、from-importの日本語表記を追加しないと決定する。** `.jpy` の自動importも導入しない。依存モジュールは事前に `.py` に変換して通常のPythonの配置を保つ。

### 4.7 例外・後処理・確認

```jpy
試す:
    もし 値 < 0 ならば:
        投げる ValueError("負数は使えません")
捕まえる ValueError として エラー:
    print(エラー)
それ以外:
    print("例外なく完了")
最後に:
    print("後処理")
```

`捕まえる (ValueError, TypeError) として エラー:` のような複数の例外型も使える。裸の `捕まえる:` は最後に置く。`試す` に続く `それ以外` は例外なくtry本体を抜けた場合に実行され、return等の条件もPythonと同じ。`最後に` はPythonのfinallyであり、強制終了を含むあらゆる状況で必ず走るという独自保証はしない。

`投げる` だけなら現在処理中の例外を再送出する。例外チェーンは `投げる 新しい例外 from 原因`、チェーン表示の抑制は `from None` を使う。`except*` は英語表記のまま使用し、日本語の `捕まえる*` は定義しない。

`確認する 条件, メッセージ` はassert。Pythonの最適化実行で省略され得るため、必須の入力検証やセキュリティ検証を担わせない。

### 4.8 リソース管理

```jpy
使う open("data.txt", encoding="utf-8") として ファイル:
    内容 = ファイル.read()
```

`使う` はファイルを開く専用構文ではなく、1つのコンテキストマネージャーを扱うwithである。`として` の省略も許可する。分解代入は `として (a, b)` のように括弧で囲む。複数のコンテキストマネージャーには通常の `with A() as a, B() as b:` を使う。`__enter__`、`__exit__`、例外抑制の意味はPythonと同じ。

## 5. 追加文法の概略

以下は追加構文の概略であり、Python全体を置換する完全な文法ではない。式の優先順位はPythonに委譲する。日本語形のブロックはすべて改行・インデントされたスイートを持つ。

```text
if_header       := "もし" PY_CONDITION "ならば" ":" | PY_CONDITION "なら" ":"
elif_header     := "それ以外でもし" PY_CONDITION "ならば" ":"
else_header     := "それ以外" ":"
for_header      := "繰り返し" PY_NAME "が" PY_EXPR "から" PY_EXPR "まで" [PY_EXPR "ずつ"] ":"
                 | ("繰り返し" | "各") PY_FOR_TARGET "を" PY_ITERABLE_EXPR "から" ":"
while_header    := PY_CONDITION "の間" ":"
function_header := "関数" PY_FUNCTION_DECLARATION ":"
class_header    := "クラス" PY_CLASS_DECLARATION ":"
return_stmt     := "戻す" [PY_RETURN_VALUES] | PY_RETURN_VALUES "を戻す"
control_stmt    := "抜ける" | "続ける" | "何もしない"
alias           := "として" | "as"
import_stmt     := "読み込む" PY_MODULE [alias PY_NAME]
try_header      := "試す" ":"
except_header   := "捕まえる" [PY_EXPR [alias PY_NAME]] ":"
finally_header  := "最後に" ":"
raise_stmt      := "投げる" [PY_EXPR ["from" PY_EXPR]]
with_header     := "使う" PY_CONTEXT_EXPR [alias PY_WITH_TARGET] ":"
assert_stmt     := "確認する" PY_EXPR ["," PY_EXPR]
```

変換後のモジュール全体をCPythonで構文・文脈検証する。単なる字句変換結果だけでプログラムを受理したことにはしない。低レベルAPI `transpile()` は未検証のPythonを返す場合があり、`compile_file()` / `run_file()` が最終検証を行う。

## 6. 代表例と期待結果

```jpy
関数 判定(点数: int) -> str:
    もし 点数 >= 80 ならば:
        戻す "優"
    それ以外でもし 点数 >= 60 ならば:
        "合格" を戻す
    それ以外:
        戻す "不合格"

繰り返し 点数 を [55, 65, 82] から:
    print(判定(点数))
```

対応するPythonは次のとおり。

```python
def 判定(点数: int) -> str:
    if 点数 >= 80:
        return "優"
    elif 点数 >= 60:
        return "合格"
    else:
        return "不合格"

for 点数 in [55, 65, 82]:
    print(判定(点数))
```

出力は `不合格`、`合格`、`優` の3行。

## 7. v0.1ではPython表記のまま使う構文

これは「未決定」ではなく、v0.1で日本語表記を追加しないという範囲決定である。

| 分野 | 使用するPython表記 |
|---|---|
| 値・論理・比較 | `True` / `False` / `None`、`and` / `or` / `not` / `in` / `is` |
| 式・代入 | 演算子、`=`、`+=`、`:=`、条件式 `a if c else b`、`lambda` |
| コレクション | リスト・辞書・集合・タプル、スライス、アンパック、内包表記 |
| 非同期 | `async def` / `await` / `async for` / `async with` |
| ジェネレーター | `yield` / `yield from` |
| パターンマッチ | `match` / `case` とそのガード |
| 型・スコープ | 型注釈、`type`、`global` / `nonlocal` / `del` |
| 高度な例外処理 | `except*` |
| import・複数リソース | `from ... import ...`、複数import、複数項目のwith |
| 組み込み・特殊名 | `print`、`input`、`len`、`range`、`self`、`__init__` など |

これらの英語構文の複数行ブロック内には、適切な文脈で日本語の文を記述できる。`async 関数` のような未定義の混合ヘッダは推測して解釈しない。

## 8. 識別子衝突・認識順

日本語語彙を全域で予約するのではなく、文法上の位置で認識する。元から英語のPython文として始まる文・ヘッダは変更しない。とくに `if の間:` や `for x in なら:` の識別子を後置構文と誤認しない。Pythonの `match` / `case` ヘッダも優先する。同名の式にJPy後置形を使いたい場合は `(match) の間:` のように括弧を使う。

代入・注釈・属性アクセスは名前として保持する。文頭の日本語構文語に続く引数には空白が必要であるため、次の区別が成立する。

```jpy
戻す = lambda x: x + 1
戻す(3)             # 名前「戻す」の関数呼び出し
obj.戻す(3)         # 属性の呼び出し
関数 f():
    戻す (3)        # return (3)
```

`戻す`、`抜ける`、`続ける`、`何もしない`、`投げる` の単独文はJPyの文になる。`確認する` の単独文はassertの式が不足しており最終検証でエラーになる。これらの語を単に式として参照する場合は `(戻す)` のように書く。`戻す + 1` は空白のあるreturn構文であり、名前の加算を式文として書くなら `(戻す) + 1` とする。

区切り語と同名の識別子・属性が最上位に複数現れて分割が曖昧になる場合は拒否する。該当する式を括弧で囲むことで区切りと区別する。文字列・コメント・括弧内部の語を区切りとして探索しない。

この規則によって曖昧な自然言語を推測せず、受理するソースと変換先を決定する。

## 9. エラー・ソース位置・変換品質

変換はトークン境界と文構造に基づく。参考実装は `tokenize` を利用するが、特定のトークナイザーを言語仕様の必須実装方式にはしない。Pythonの `tokenize` は一般の非Python入力を保証するAPIではないため、対応CPythonバージョンごとの受け入れテストを必要とする。

改行コードの正規化を除き、変換によって物理行を増減しない。JPy構文の認識エラーは元の `.jpy` のファイル名・行を示す。CPythonによる最終検証およびrun時のトレースバックも元ソースに対応する行番号を保つ。

**v0.1で保証するのはファイル・行の対応であり、変換後の列番号の完全な逆変換ではない。** 参考実装が直接報告するJPyエラーの列は元トークンの位置。CPythonの診断文・下線・列番号には変換済みPythonの位置が現れる場合がある。生成 `.py` を直接実行する場合、トレースバックのファイル名はその `.py` となる。

構文エラー、関数外return、ループ外break等はCPythonの最終検証に委譲する。実行時の例外を握りつぶしたり、別の実行意味論に置き換えたりしない。構文不正な入力ではcompileは出力せず、runはアプリケーションを実行しない。

## 10. 参考ツールの意味と互換性契約（規範）

**JPy の主成果物は言語変換仕様であり、CLI は参考実装にすぎない。** ただし、以下のモードの意味は v0.1 の公開後に入れ替えてはならない。

### 10.1 `compile`: Python ファイルへの純粋変換

```sh
jpy compile main.jpy                # デフォルトで build/main.py を出力
jpy compile main.jpy -o main.py     # 出力先を明示
jpy compile main.jpy -o main.py --force  # 既存ファイルを明示的に上書き
```

このモードの契約:

1. `.jpy` の言語構文を対応する Python 構文に変換し、UTF-8 の **`.py` ファイルを書き出す**。
2. **アプリケーションコードを実行しない**。CPython による構文・意味的制約の静的検証は許可される。
3. 生成 `.py` は JPy ランタイムに依存せず、**独立に CPython で読み込み・実行できる**。
4. 入力の `.jpy` に変更を加えず、既存の出力 `.py` を暗黙に上書きしない。
5. Python 生成物の物理行番号は元の `.jpy` と一致する。

### 10.2 `run`: 元の `.jpy` を直接 CPython で実行

```sh
jpy run main.jpy
jpy run main.jpy -- arg1 arg2
```

このモードの契約:

1. **元の `.jpy` を実行対象とする**。ユーザーは `.py` への明示的変換を必要としない。
2. JPy 構文を **メモリ内でだけ** Python 構文に変換し、同じ CPython プロセスでコードオブジェクト化して実行する。**変換済み `.py` を一時ファイルとしても書き出さない**。
3. 独自 JPy VM や独自 Python 実装は利用しない。未変換の日本語文法そのものを CPython に直接解釈させる方式でもない。
4. `__name__ == "__main__"`、`__file__`、`sys.argv`、スクリプト所在ディレクトリからの Python import を通常の CPython スクリプト実行に近づける。`__file__` とトレースバックの対象パスは `.jpy` である。
5. `run` は**ファイル変換・ビルド成果物生成の手段ではない**。アプリケーション自身が行うファイル出力や Python 標準の import キャッシュはこの禁止範囲に含めない。

### 10.3 共通内部実装と、混同してはならない意味

構文変換器自体は両モードで **同じ変換規則**を使う。一方、**出力と副作用の契約は別**である。`compile` が実行を始めたり、`run` が実行のための `.py` を残したりする変更は互換性を破壊する。

特定の CLI 名・ライブラリ名は仮称であり、公開前に他プロジェクトとの衝突を確認すること。

### 10.4 PyInstaller / Nuitka との連携（規範）

**PyInstaller と Nuitka には `compile` モードで生成された通常の `.py` を入力する。** 両ツールへ `.jpy` を直接渡すこと、あるいは `run` モードをバンドルの入口にすることを v0.1 の互換性要件にしてはならない。

```sh
jpy compile main.jpy -o build/main.py
python -m PyInstaller --onefile build/main.py
python -m nuitka --mode=standalone build/main.py
# standalone で動作確認してから
python -m nuitka --mode=onefile build/main.py
```

- この方法では配布された Python アプリケーションへ JPy 実行ランタイムを追加する必要はない。
- `.jpy` 依存モジュールは v0.1 ではすべて事前に `.py` に変換して、通常の Python モジュール配置を保つ。`.jpy` の直接 import は非対応。
- PyInstaller / Nuitka 固有の追加依存、動的 import、データ同梱、相対ファイルパス、ネイティブコンパイラの制約は各ツールに従う。任意の環境でのパッケージング成功までは JPy 仕様が保証しない。
- 将来、便利コマンドを追加する場合も **内部で `compile` 由来の通常の `.py` を渡すだけ**とし、`compile` / `run` の意味を変更してはならない。

## 11. 非目的とリリース範囲

自然文の自由解釈、値・演算子・ライブラリAPIの日本語化、独自型検査、独自VM、`.jpy` の自動import、依存関係解決、JPyからの自動パッケージングを追加しない。§7の構文はPython表記で使用する。

文法を決定したことと、全プラットフォーム・全依存関係での品質検証完了は別である。正式なリリース認定、パッケージ名、ライセンスの確定はこの文法決定の対象外。既存の `各` / `条件 なら:` / `値 を戻す` は維持し、未告知で削除しない。

## 12. 受け入れ基準

実装は少なくとも次を検証する。テストは仕様に追従し、実装の都合で意味を変更しない。

1. §6の変換・出力が一致し、日本語と英語のif/elif/else/for/whileを混在できる。
2. 汎用forのリスト・辞書・分解代入・イテレーター、0回反復、ループelseとbreak/continueがPythonと等価。
3. 範囲反復は終了値非包含。正・負・0の増分、空範囲、型エラー、各引数の評価回数・順序、rangeの名前解決を検証する。
4. 関数・クラス・戻り値、try/except/else/finally、raise/from、withの後処理、assertと最適化が対応するPythonと等価。
5. 通常のPython文、式、同名識別子の呼び出し、文字列・コメント・f-stringを誤変換しない。
6. 複数行の式、UTF-8/BOM/改行、構文エラーのファイル名・行、無効な区切り・インラインスイート・セミコロンを検証する。
7. compileはアプリを実行せず、通常の.pyのみを出力し、無断上書きしない。生成物はJPyなしのCPythonで動く。
8. runは元の.jpyを対象にCPythonで実行し、変換済み.pyを一時ファイルとしても書き出さない。
9. 両モードは同じ言語変換規則を使い、同じプログラムの結果が一致する。配布ツールの入口はcompileの生成物である。
